## PlayerBar 收口：宽度贴合操作栏 + 透明度再降

用户看图反馈「宽度适配操作栏宽度，再将透明度」→

- **宽度贴合操作栏**：删掉固定 `sm:w-[360px]`，改 `sm:w-fit sm:max-w-[min(380px,calc(100vw-3rem))]`。实测卡片 292px、操作行 290px、内嵌仅 1px，三行共用操作栏宽度、左右边距统一，左侧大片空白消失。
- **透明度再降**：桌面 `bg-base-2/40 → /30 → /25`，并把 `backdrop-blur-xl → blur-lg`（24px 强模糊会把背景磨成均匀雾面、看不出地球，降到 16px 后星点/网格线能透出）。实测 `oklab(... / 0.25)`，LIVE 态文字仍清晰。
- 验证（CDP）：LIVE 态 `meta="🇦🇷 · Argentina"` 国旗在行首、`bg /0.25`、卡片=操作行宽；构建通过。
- 反复调透明度的根因：base-2 本身很暗（oklab L≈0.16），叠加暗色地球背景下，即使 25% 也不显亮；卡片在左下角、背后多为暗星空而非球体中央，故"看到地球"的透出感天然有限。再低（< /20）会开始牺牲 10px meta 可读性，故停在 /25 + blur-lg。

## 修复：抽屉「附近」始终提示没拿到位置

用户反馈：打开抽屉「附近」tab 始终显示「没拿到你的位置」。

根因排查（CDP + node 实测）：
- 管道正确：浏览器内 `fetch` ipwho.is 返回 200、777ms、结构正常；省份解析 `matchRegion` 能处理 `Guangdong`/`GD`。
- 真因：`useWhereAmI` 依赖的 `ipwho.is` 是境外 `.is` 域名，在国内网络下易被墙/限速；原 `TIMEOUT=2500ms` 偏短，请求被 abort → `fetchLocation` 永远返回 null → 抽屉走 `province=null` 分支显示「没拿到位置」。备选 `ipapi.co` 实测 429 限流、`api.ip.sb/geoip` 200+`ACAO:*` 可用。

修复（两个文件）：
- **`src/lib/whereami.ts` 重写**：
  - 超时 `2500 → 5000ms`。
  - 定位源 `PROVIDERS` 多源并行竞速（ipwho.is 主 + api.ip.sb/geoip 兜底），各自带 5s 超时；`raceProviders` 优先取「认得出省份」的结果，无省份退而取任一非空结论（境外 IP），全失败才 null。归一化 `RawGeo` + `toWhere` 复用原逻辑。
  - 新增 `locateViaBrowser()`：用 `navigator.geolocation` 拿真实经纬度 → `nearestRegion` 反查省份（国内网络最稳的一条路，但需授权，故不默认触发）。
  - `useWhereAmI` 新增 `browserLocating` + `requestBrowserLocation`（useCallback 守卫重入）。
- **`src/components/MapDrawer.tsx`**：`useWhereAmI` 解构 `browserLocating`/`requestBrowserLocation`；「附近」空状态文案改为「没拿到你的位置，可点下方按钮用设备定位」，并在 `!province && !locating && !browserLocating && supportsGeolocation` 时渲染「用我的位置」按钮（带定位图标）。`supportsGeolocation` 守卫非安全上下文/无 geolocation。

验证：typecheck 通过；CDP 打开抽屉（沙箱境外 IP 复现 province=null 场景）→ 文案与「用我的位置」按钮均渲染（hasGeoButton:true）。国内环境预期：多源竞速拿到省份即直接显示本地台，否则按钮用设备定位兜底。
