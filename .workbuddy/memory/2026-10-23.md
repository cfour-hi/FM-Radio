# 2026-10-23 · FM-Radio 立项与方案验证

## 项目定位
全球 FM 电台收听站。Vite + React + TS，纯静态产物，无服务端、无流代理。

## 已确认决策
- 只接受 https 流（占目录 66%），放弃 http-only 台；因 Cloudflare 协议 2.2.1(j) 禁止代理服务，不做免费代理层。
- 构建层保留 TS（曾讨论退 JSDoc，最终保留）。
- 不引入 shadcn/ui；用 CSS 变量设计令牌 + 原生 `<dialog>` + clsx/tailwind-merge。
- 地图：MapLibre GL + 天地图 WMTS 栅格源（key 走 `VITE_TDT_KEY`，域名白名单）。
- 播放：原生 Audio 全局单例 + hls.js 惰性加载（HLS 约 10%）+ MediaSession。
- 数据：radio-browser.info，多镜像随机轮询，IndexedDB(Dexie) 缓存，首屏只拉 200 条。

## 实测结论（可复用）
- radio-browser 按点击取 8000 条：https 66%、http 34%；有经纬度仅 25%（2028/8000）；MP3 66%、AAC 16%、AAC+ 12.5%、OGG 1%、HLS 约 10%。
- 8000 条 JSON = 9.1MB，全量不可行；需分层加载。
- https 流抽样 80 台：可播率 94%，但首字节 >2s 占 71% → 「调谐中」要做成仪式性反馈，不能静默转圈。
- 天地图：无 key 时 CloudWAF 返回 418；带 tk + 浏览器 Referer 即 200 → MapLibre 直连瓦片可行，不必依赖官方 SDK。
- 天地图 `ibo`（全球境界）背景透明（PNG tRNS），但 z0–z2 是空白瓦片，z3 起才有数据；只有境界线（含行政界），**无海岸线** → 不能当底图，只能做边界增强层。
- 天地图 `vec` 从 z1 起有数据 → 全球视野只能靠 vec。
- 天地图 `cva` 注记到 z7 为止，z8 空白。

## 视觉方案（待用户确认 B 还是 D）
- B：vec + 深色底 + 降不透明度（合规，最简）
- D：vec 压暗 + ibo 叠加（边界更突出）
- 禁用：对瓦片做 raster 反色/改色、拼图导出、矢量描边提取边界。

### 踩到的三个坑（都会导致地图整块不可用）

1. **容器高度塌成 0**：MapLibre 给容器加 `.maplibregl-map{position:relative}`，与 Tailwind 的 `.absolute` 同优先级但后加载，覆盖掉了定位，`inset-0` 失效 → 高度 0 → 画布退回 400×300 → 一片黑。解法：外层 `absolute inset-0` 包一层，地图容器自己只写 `h-full w-full`。
2. **开发环境 worker 加载失败**：`optimizeDeps.exclude: ["maplibre-gl"]`。maplibre 用 `new URL('./maplibre-gl-worker.mjs', import.meta.url)` 拼 worker 路径，预打包后指向不存在的文件。
3. **生产构建不产出 worker**：那个路径是运行时拼的，打包器识别不了。解法 `import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url"` + `setWorkerUrl(workerUrl)`，产物里才会出现 `maplibre-gl-worker-*.js`（518KB raw / 143KB gzip）。**这个必须用 `vite preview` 验，dev 看不出问题。**
4. 聚合状态画不出选中环：聚合时源里没有单点这一条，环图层永远是空的（`clusterMaxZoom=5` 时 z5 仍走聚合瓦片）。改用 `Marker` + DOM 脉冲标记，且 flyTo 推到 5.4。

## P5.5 坐标清洗（用户提问「中国电台为什么很少」引出）

诊断结论：**不是中国台少，是源数据里中国台不填坐标。**

- 目录：CN 2,441（全球第 5，美 8,736 / 德 6,564），HK 98 / TW 219 / MO 35。
- 坐标覆盖率（前 500 条样本）：BR 38% / US 35% / DE 28% / KR 24% / **CN 5%**；中国全量更差：2,175 条里仅 28 条有坐标（1.3%），https 过滤后 17 条。
- 构建脚本每国只扫点击量前 160 条 → 中国命中 10 条，就是图上全部。
- 原因：radio-browser 是众包库，欧美用户录入时点了坐标；中国台多为批量导入，只填省份且用威妥玛拼音（Chekiang / Kiangsu / Kwangtung / Szechuan）。
- **隐藏资源**：中国 2,175 条里 1,690 条有 `state` 省份字段（其中 1,451 条 https）。省名→省会坐标可让中国上 1,400+ 个点，属「省级近似」，用户暂未采用。

修复（方案 A）：`scripts/build-map-data.mjs` 新增 `dropOutliers()`——同国点位算最近邻距离，超过 `max(15°, 中位数×8)` 视为标错大洲。同时把采样改成「先收全 160 条候选 → 清洗 → 再按配额截断」，否则剔掉一个错点就补不回来。

- 剔除 15 个：13 个真错（广东音乐之声标在大西洋 39°N/36°W、BRTV 北京经度填成 40 落在土耳其、US DnB&EDM 标在德国、AT 台标在佛州等）+ 2 个误杀（夏威夷檀香山、俄罗斯哈巴罗夫斯克）。
- 结果：1,763 → 1,751 个点；中国 10 → 7（剩下苏州/南京/合肥/广州/上海/佛山，全部合理）；复核无残余离群点。
- 阈值为什么用「中位数×8」：俄罗斯、智利这类横跨几十度的国家，中位数本身就大，阈值随之放大，不会误删远东点；反之大城市密集国家中位数接近 0，靠 15° 兜底。
- **已知代价**：真正孤悬海外的台会被当成错误。要更准需要国家级外包矩形数据，暂不引入。

## 大陆粒子层（land-dots）

用户问「地图能否做成 3D 地球、用粒子组成大陆轮廓」。先做了 2D 版验证美学方向（3D 球暂缓）。

**结论：3D 可行但要谨慎**
- maplibre-gl 6.15 原生支持 `projection: "globe"`，不用换库；天地图瓦片实测返回 `Access-Control-Allow-Origin: *`，可直接贴球面。
- 三条路线：① MapLibre globe（最小改动、合规稳，但符号层做不出深度明暗）；② Three.js 纯粒子（视觉最好、包体更小，但陆地边界来自 Natural Earth，中国边界表达不合规）；③ Three.js 球 + 天地图贴图 + 粒子（最好，工作量最大）。
- 3D 的固有代价：一次只能看 64%（1751 个点里 1114 个可见），发现效率低于 2D。

**已落地：2D 点阵层**
- 数据：`scripts/build-land-dots.mjs`（`pnpm map:dots`）把 NE 110m land 栅格化 → `public/land-dots.json`，6,910 点 / 74KB / gzip 31KB。轮廓数据放 `scripts/data/ne_110m_land.geojson`（138KB，可离线构建）。
- 图层：`bg → vec → land-dots → ibo → stations`，粒子在**瓦片之上、国界之下**，`maxzoom: 5` 到城市尺度退出渲染。

**三个必须记住的坑**
1. **球面均匀采样在 Mercator 地图上会出一圈圈同心弧**（南美以南、澳洲以南最明显）——球面等距的点被墨卡托纵向拉伸后不再等距。2D 版必须用**墨卡托网格采样**；球面斐波那契只适合 3D 球。
2. **粒子放在瓦片下面会被冲成灰白**。瓦片的陆地填色盖住暖色，只剩噪点。必须压在瓦片之上；重影不明显，因为瓦片已压到 0.1。
3. **密度按点距算，不按点数算**。185×120 网格 ≈ 陆地 6,900 点、点距约 5px、点径 2px 刚好透气；260×170 会降到 3.5px 间距，陆地糊成一整块米色。
- 另外：`#d6bc94` 这种低饱和暖色在暗底上会被抗锯齿吃成灰白，要 `#c99a5e` 这一档才立得住。

**底图不透明度改成随缩放插值**：`0→0.10, 2.5→0.13, 3.6→0.20, 5→0.27`。全球视角让粒子主导，放大后底图回到原来的 0.27。之前固定 0.27 时底图陆地填色比点阵还抢眼。

**验证**：typecheck / build 通过；dev 与生产预览均正常；粒子层开关帧率无差别（60fps，headless 上限）、拖拽 61fps；聚合点击 1.11→3.00、随机点亮 zoom 5.40、回到世界、z6 粒子退出渲染全部通过。移动端 340px 宽点距压到 1.84px 仍可辨，未做单独适配。

## 3D 球体已落地（走路线 ① MapLibre globe）

**选型**：没有引入 Three.js。用 maplibre-gl 6.15 原生的 `projection: { type: "globe" }`，底图仍是天地图瓦片，合规基线完全不动。`src/map/tdt.ts` 里的 `PROJECTION` 常量控制，平面路径与 `worldBoundsFor` 都保留着，改一行即可切回 2D。

**两套点阵，不能共用**（关键认知）
- `pnpm map:dots` → `public/land-dots.json`：墨卡托网格采样，6,910 点，gzip 31KB，给平面地图。
- `pnpm map:dots:globe` → `public/land-dots-globe.json`：斐波那契球面采样 + 切向抖动，**12,163 点**，130KB / **gzip 54KB**。
- 采样空间必须和显示空间一致：球面采样铺 2D 会出同心弧，墨卡托网格铺球会把两极挤成条纹。
- 密度按「短边 × 0.84」的屏幕点距反推：42000 候选 ≈ 1° 点距 ≈ 球径 535px 时 4.7px，与平面版 4.9px 对齐。

**球体直径是量出来的，不是算出来的**
- globe 是透视投影，`project()` 反推半径会随 zoom 漂移（1.5 时高估 11%，2.0 时高估 19%）。
- 用 `gl.painter.context.gl.readPixels` 读帧缓冲找非背景 bbox，实测 h=535 时：zoom 1.4→379px、1.6→423、1.8→469、2.0→521。
- 归一化成直线：`d/h = 0.0874 + 0.4433 · zoom`，反解即得。常量写死在 `WorldMap.tsx` 的 `GLOBE_D_BASE / GLOBE_D_PER_ZOOM`。
- **不能用 fitBounds**：球体视觉边界（±90°）比经纬度范围（±180°）小得多，fitBounds 必把球上下切掉。
- 直径按 `min(width, height)` 算，否则竖屏手机（340×555）球会被左右裁切。

**放大后必须提亮底图 + 加注记，否则等于没有地图**
- 新增 `tdt-cva` 注记层，`minzoom: 4`，opacity 4→0, 4.8→0.55, 5.6→0.88。
- 天地图注记是**深色文字**，底图压在 0.1–0.27 时一个字都读不出 → 所以 `vec` 的 opacity 曲线改成 `0→0.10, 2.5→0.13, 3.6→0.22, 4.6→0.42, 5.5→0.62, 8→0.70`。
- 代价：z5+ 地图变浅色（接近天地图原色），与暗色 UI 有割裂感，但可读性优先。不要试图用 raster 反色/调色去解决——那是改地图表示。

**`.map-vignette` 必须随缩放淡出**
- 这层 CSS 遮罩是 2D 时代做「面板感」的，全球视角下和球体很配；但放大后它会啃掉边缘地名。
- 做法：`map.css` 里 `opacity: var(--map-vignette, 1)`，WorldMap 在 zoom 事件写变量（z≤3.2 → 0.55，z≥4.8 → 0）。

**大气层**
- `map.setSky()`（style 里没有 sky 层类型，TS 不认），**必须 `map.once("load")` 之后调**，否则抛 "Style is not done loading" 直接白屏。
- `fog-color` 必须等于页面背景 `#07080b`，否则平面模式下会多一圈不该有的暗角。
- `atmosphere-blend` 在 globe→mercator 过渡后不会自动归零，要按 zoom 手动关（z≥3.6 → 0）。

**验证**：typecheck / build 通过；生产预览无异常请求、`land-dots-globe.json` 200。交互 8/8：初始 z=1.7、点聚合 1.70→2.00、回到世界复位 [24,22]、拖动旋转 24°→70.3°、随机点亮 z=5.40 + 脉冲环、静止与拖动均 60fps。移动端 340×555 球完整不裁切。

## 省→省会归属 + 取消「兜底归北京」

**用户规则（最终）**：台名只有省份没有城市时，归属**省会城市**；无地名线索的台**不**兜底（先要求归北京，随后撤回）。

**省→省会**
- 不再用 `PROVINCE_RADIUS = 80`（省域大圈），改为 `capitalFor(province)`：在 `cn-places.json` 里找离省会坐标 ≤30km、人口最大的城市点，半径用该城市的人口档（40/26/15/10km），`place` 显示省会名（如「昆明」）。
- 关键：返回的 `kind` 必须是 `"city"`，让省台和「台名直接命中省会」的台分到**同一个散点组**（`city:lat,lon`），否则两组互不相让、点直接叠在一起。
- 另加 `provincial: true` 标记，只给真实坐标校验用（省台真实坐标可能在省内任何地方，不能拿 300km 卡）。

**新增的三条匹配修正（都靠实测踩出来）**
1. **两字城市名切在省名内部**：「广**东城**市之声」「辽**宁乡**村广播」「黑**龙江**卫视」曾被甩到重庆东城、湖南宁乡、齐齐哈尔。做法：`findCity` 先算省名在字符串里的区间，两字城市命中与省名区间重叠就跳过；只有省名后紧跟「市」才放行（「吉林市交通广播」→ 吉林市，「吉林新闻综合广播」→ 长春）。
2. **`state = "Shanxi"` 歧义**：陕西旧拼法也是 Shanxi，「陕西交通广播」被判到太原。台名里的**汉字**省名因此提到 `state` 之前判断（`findProvince` 改为返回 `{province, cjk}`）；拉丁写法仍交给 state。
3. **城市表显示名**：
   - 假名别名：「ウルムチ市」含「市」字骗过 `hasCJK`，乌鲁木齐主名一度是「ウルムチ」。加 `KANA` 过滤。
   - 繁简：不维护对照表，改用**全表字频**——同长度时选字符出现次数更多的写法（贵 225 vs 貴 44）。贵阳/银川/重庆/哈尔滨全部转正。
   - 「中国上海」：上海记录的中文别名里有这条 4 字写法，最长优先选中。过滤「中国」前缀别名。

**兜底归北京（已撤）**：曾把 181 条无线索的网台全部散到北京外围 75km 并作为额外名额不占配额。撤回原因：那样北京会多出 181 个编造位置的点，形成一个巨型聚合团。现在仍是「无坐标 → 不上图」。

**结果**：中国 260 点 / 155 个落点 / 161 城市；真坐标 8、台名城市 433、省份推断 345、国家级 42、无线索 181。`map-stations.json` gzip 159KB，首屏仍 136.63KB。

- 旧的 `d/H = 0.0874 + 0.4433·zoom` 只在原来 535px 高的面板成立。整屏 811px 高时同一 zoom 下球只有 57%。
- 改成 `measureGlobeDiameter()`：取与中心相距 90° 弧长的赤道点（`[center.lng+90, 0]`），它必在轮廓圆上，project 后与中心的水平距离×2 就是直径；`solveGlobeZoom()` 迭代 3–4 次（d ∝ 2^(0.88z) 只当步长）。

## 修复：缩放后星空遮罩露出「大圆」

**现象**：地球缩放后，球体背后出现一个比球大很多的圆形边界——球外星空被挖掉一大块，露出暗盘。

**根因**：`.map-stars` / `.map-nebula` 用 `radial-gradient` mask 挖空球体那块，半径取自 CSS 变量 `--globe-r`；而 `--globe-r` 只在 `fitWorld()` 里按目标尺寸写一次（初始加载 / 窗口 resize / 回到世界）。球体在屏幕上的半径随缩放连续变化，遮罩却不跟。实测（1400×900）：

| zoom | 实测球半径 | 旧 `--globe-r` | 后果 |
|---|---|---|---|
| 2.42（世界视角） | 394 | 396px | 刚好对齐 |
| 2.0 | 312 | 396px | 挖大了 → 露出无星暗盘（用户看到的「大圆」） |
| 3.0 | 534 | 396px | 挖小了 → 星星压在球面上 |

**修复（2 处）**：
- `WorldMap.tsx`：新增 `syncGlobeRadius()`——复用已有 `measureGlobeDiameter()`（沿中心经线扫描取最大投影距离，实测轮廓半径）在每次 `zoom` 事件里重量并写 `--globe-r`；`globeRadiusZoom` 缓存上次量测的 zoom，变化 <0.004 时跳过（量一次要投 120 个点）。`fitWorld` 仍写 `target/2` 作首帧近似值，并把它置 `NaN` 强制下一次 zoom 重量。
- `map.css`：两处 mask 从硬边（`transparent r` → `black r+2px`）改为羽化过渡（星云 r-30 → r+70，星星 r-2 → r+26），亚像素误差藏进渐变，视觉上像「大气层吃掉星光」。

**验证**：世界 394/394、z2.0 312/312、z1.5 234/234、z3.0 534/534 全部 0 差值；真实滚轮 z2.06→0.63 逐档 0–1px；视口 1400×900/900×700/375×667/1600×1000 全部 0 差值；环形亮度剖面在球缘（r≈284）之后无台阶；端到端回归 12/12；无 console error。

**教训**：凡是「用 CSS 遮罩去对齐 WebGL 渲染物」的地方，几何参数不能只在布局时算一次——相机会动，遮罩就得跟着量。

## 修复：选中电台卡片与播放条左下角压叠

**现象**：点地图上的台后，左下角「选中电台信息卡」（国旗+台名+地区+收听+收藏+×）和播放条叠在一起，卡片下半截被播放条盖住。

**根因**：两处都写死 `bottom` 落在左下角——`StationCard` 是 `absolute inset-x-3 bottom-3`，`PlayerBar` 是 `fixed bottom-6 left-6`（桌面）/ 贴底全宽（移动），谁也没让谁。而且播放条高度不是常量（idle 小胶囊 ~30px / 播放中卡片 ~58px，台名换行、错误提示还会再变高），卡片没法用固定 offset 坐上去。

**修复（2 处）**：
- `PlayerBar.tsx`：用 `useLayoutEffect` + `ResizeObserver` 把播放条真实高度写进 `document.documentElement` 的 `--player-h`（idle 和播放中两个分支的根元素都挂 `ref={setBarEl}`）。
- `MapPage.tsx`：选中卡片容器从 `inset-x-3 bottom-3` 改为 `bottom-[calc(var(--player-h,58px)+10px)]`（移动）/ `sm:bottom-[calc(var(--player-h,58px)+34px)] sm:left-6 sm:w-[380px]`（桌面），卡片 `max-w-[340px]`→`380px`，与播放条左对齐同宽，形成一列。

**验证**（CDP）：桌面卡片 `{24,700,380×108}` / 播放条 `{24,818,380×58}`（间距 10px），移动卡片 `{12,496,351×108}` / 播放条 `{0,614,375×53}`（间距 10px），均无重叠、左对齐同宽、无 console error。播放条的 ERROR 是 headless 自动播放被拦截（预期，非 bug）。

**复用点**：`--player-h` 由 ResizeObserver 动态发布到 documentElement，任何「要贴着播放条上方定位」的元素都能用它，不用再猜高度。

## 选中卡片与播放条功能重复：重新设计（≈23:10）

**问题**（用户截图）：左下角选中电台卡片和播放条各显示一遍台名、地区、播放/暂停——功能重叠。
